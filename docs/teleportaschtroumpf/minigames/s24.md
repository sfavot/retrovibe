# S24 « Le Puzzle »

Fonction d'entrée `2e6a:0001` (2 028 octets, 730 instructions ; appelée par `1a3c:002a` et `28a3:00ad`). Code : `scenes/minigames/s24-puzzle.ts` (`createPuzzle`, `PuzzleScene`). Tests : `test/teleportaschtroumpf/minigames/s24-puzzle.test.ts`. Confiance : **sûr** pour le déroulé, les tirages, les paliers de points et les zones (décompilation et désassemblage lus en entier) ; **probable** pour les bornes du curseur et les sons (voie).

## Principe

Un tableau (cinq possibles, `s24a001d` à `s24a005d`) est montré en entier quelques secondes. Puis `niveau + 3` rectangles de 36 × 21 pixels y sont **découpés** : chaque trou est rempli de gris clair (`0x7F`) et son contenu est recopié dans une rangée de vignettes en bas de l'écran. La vignette de rang 0 est encadrée : le joueur clique le trou d'où elle vient. Un clic juste efface le trou (le tableau reparaît à cet endroit) et l'encadré passe à la vignette suivante (rang croissant). Un clic sur un **autre** trou, ou le temps écoulé, termine la partie. Quand tous les trous sauf le dernier sont trouvés, la partie est gagnée (le dernier se devine).

Le curseur est le sprite 0 de `s24a000s.hy8`, dessiné par la scène (`DS:190 = 1` : le curseur du système est coupé) à la position de la souris ; au clavier, les flèches le déplacent de 2 px par tick (`Pointer`) et Espace clique.

## Déroulé de `2e6a:0001`

1. **Sons** : `s24a001b.voc` (bruit juste, `DS:7C78`) et `s24a002b.voc` (bruit faux, `DS:7C7C`) sont chargés.
2. **Niveau** : `DS:6F37 == 0x18` (l'indice de l'oiseau vise S24) : remis à 0, niveau 0. Sinon le niveau du joueur (`DS:6EB6 + joueur × 0x14`, 0..2). `n = niveau + 3` trous.
3. **Tableau** : `rand × 5000 / 0x8000 % 5 + 1` → `s24a00%dd.mcg` (le format `s24a0%dd` n'est pris qu'à partir de 10, jamais). Premier tirage de la scène. Affichage (`13fc:0150`, fondu d'entrée), copie dans le fond B.
4. **Aperçu** : `1f33:0279(5 − niveau)` : attend `5 − niveau` secondes (5, 4, 3) ou un clic gauche ; puis `1f33:036d` (relâchement des boutons, au plus 5 s).
5. **Tirage des trous** (`2e6a:00f4..028b`), pour `i` de 0 à `n − 1` :
   - position : `x = rand × (0x107 / n − 5) / 0x8000 + i × (0x107 / n) + 6` (un trou par colonne de `0x107 / n` px : 87, 65 ou 52), `y = rand × 0x7B / 0x8000 + 4` ; refusée si elle chevauche un trou précédent (`|Δx| < 0x26` **et** `|Δy| < 0x17`) : les deux tirages sont alors refaits ensemble ;
   - rang de vignette : `rand × 5000 / 0x8000 % n`, refusé s'il est déjà pris (permutation de `0..n−1`) ; le trou de rang 0 est le premier à trouver.
6. Souris replacée au centre (`14b3:0039`, `0xA0, 0x64`), **chrono 2** démarré, limite `40 − 5 × niveau` s (40, 35, 30).
7. **Boucle** (aucune cadence : une itération par rafraîchissement, soit un tick ici) :
   - musique relancée si rien ne joue (`15f9:089f`) ; lecture de la souris ;
   - fond restauré (B → A) ; pour chaque trou non trouvé, dans l'ordre : **vignette** recopiée de la position du trou vers (`0x20 + 0x2B × rang`, `0x9F`) (`13fc:0427`, copie opaque 36 × 21), **trou** rempli de `0x7F` (`328a:0022`, bords compris), puis si le curseur est dans `[x, x + 0x24[ × [y, y + 0x15[` : deux cadres `32af:0006` : (x − 1, y − 1)–(x + 0x25, y + 0x16) en `0x7E`, (x − 2, y − 2)–(x + 0x24, y + 0x15) en `0x7F`. Le **dernier** trou de la liste qui contient le curseur est « le trou survolé » ;
   - cadre `0x7E` autour de la vignette à trouver : (`0x1E + 0x2B × rang`, `0x9D`)–(`0x45 + 0x2B × rang`, `0xB5`) ; curseur (`31fe:0481(0, x, y)`) ; affichage ;
   - bouton gauche (`DS:3FCE == 1`) : trou survolé = trou attendu → bruit juste (seulement si aucun son ne joue : `348d:0b42(1, 0)`), trou trouvé, compteur + 1, trou attendu suivant = le non trouvé de plus petit rang ; autre trou survolé → bruit faux (lancé dans tous les cas), échec ; vide → rien. Dans les trois cas `1f33:036d` attend le relâchement (au plus 5 s) ;
   - fin si échec, ou compteur ≥ `n − 1`, ou chrono ≥ limite (lu après le relâchement).
8. **Fin** : curseur retiré (`DS:190 = 0`), fond restauré, un double cadre autour de chaque trou **resté ouvert**, affichage ; **fondu sonore** `1343:0037` (volume de son niveau à 1, un cran toutes les 20 centièmes), son coupé ; **le chrono est lu ici** (`1f33:019a(2)`, avant la voix) ; puis :
   - échec (mauvais clic) : voix `s24b` + (1 + `rand × 9`), `1e52:00a8` (une fonction vide) ;
   - temps écoulé : voix `s24b` + (10 + `rand × 9`) ;
   - réussite : tableau restauré sans cadre, voix `s24c` + (1 + `rand × 13`), puis `1e52:00ad(joueur, points)`.
   Toutes les voix sont attendues en entier (`1f33:03a7(1)` : un clic gauche les coupe). `1f33:0009` (police, relâchement, fond B → A) termine.

La voix d'accroche `s24a` est jouée avant la scène par l'appelant (`28a3:04dc`).

## Gain et issue

`MinigameOutcome` `{ kind: "points", points }` : **3, 2 ou 1 point**, c'est bien « 1 à 3 » ici (contrairement à S51), selon les secondes lues **après** le fondu sonore : moins de `limite / 3` → 3, moins de `2 × limite / 3` → 2, sinon 1 (`2e6a:0789..07b0`, divisions entières signées). Au niveau 0 (limite 40) : < 13 s → 3, < 26 s → 2 ; niveau 1 (35) : < 11, < 23 ; niveau 2 (30) : < 10, < 20. Le fondu ajoute jusqu'à 3 s (15 crans de 0,2 s au volume 15, moins au volume bas) : une partie finie en 10 s de jeu vaut 2 points, non 3, au niveau 0. Échec (mauvais clic ou temps écoulé) : 0, `1e52:00ad` n'est pas appelé. Gagner au dernier instant est possible (le test de fin donne la victoire avant le temps écoulé) et vaut 1 point. `Game` plafonne le total du joueur à 60.

## Niveaux et indice de l'oiseau

Le niveau du joueur règle **le nombre de trous** (3, 4, 5), **le temps** (40, 35, 30 s) et **l'aperçu** (5, 4, 3 s) : plus le niveau est élevé, plus la scène est **difficile** (contrairement à S51 ou S32). L'indice de l'oiseau (`DS:6F37 == 0x18`) force le niveau à 0 : 3 trous, 40 s, 5 s d'aperçu, comme l'écrit `rules.md` §5 (« niveau forcé à 0 ») ; il est consommé (remis à 0).

## Commandes

Souris : le curseur suit le pointeur, clic gauche = cliquer un trou. Clavier : flèches = 2 px par tick, Espace = clic gauche. Le clic droit (Entrée) n'a aucun effet dans la partie. Un clic coupe l'aperçu et les voix de fin.

## Écarts

- **Sons** : les bruits juste et faux passent par le **canal de bruitage mélangé** (`348d:0b42(2, ptr)`, `voice.playEffect`, `engine.md` §5.2 bis) : la musique n'est pas coupée. La condition « rien ne sonne » du bruit juste est `voice.effectPlaying` (`0b42(1, 0)`) ; le faux remplace un bruitage en cours. Les voix de fin restent sur la voie. Pas d'écart.
- Le bouton est lu comme un appui (`justPressed`) : un clic plus court qu'un tick compte, alors que l'original lit l'état du bouton à chaque rafraîchissement. Le survol est calculé à chaque tick sur la position réelle du curseur.
- Bornes du curseur : celles de l'écran (aucune borne propre dans le code ; **probable**).
- `1f33:0273` (lecture des touches) et `1764:018a` (pompe) ne sont pas reproduits : sans effet visible.
- La musique n'est pas retenue pendant le jeu (l'original la relance dans la boucle) ; elle l'est (`holdMusic`) à la fin, pendant les voix.
- Le fondu sonore remet le volume à la valeur du joueur à la fin (l'original laisse le DSP bas jusqu'au son suivant), comme S28, S29 et S35.
- Les aides propres à la partie (chrono d'inactivité, voix d'indice) n'existent pas dans cette scène.
